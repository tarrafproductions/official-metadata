## EISENHERZ и Jordan: точные соответствия для сайта

Владелец сообщил, что эти обложки отображаются друг на месте друга. При визуальной проверке текущего GitHub обе привязки уже соответствуют названиям, напечатанным на изображениях. Поэтому в источнике сохранены следующие правильные пары:

| ID релиза | Название | UPC | Архивная обложка | Файл для сайта |
| --- | --- | --- | --- | --- |
| SNG-160 | EISENHERZ | 199943938454 | COV-025 | [cover-160.webp](../assets/covers/by-release/cover-160.webp) |
| SNG-218 | Jordan - الأرض المقدسة | 882436167232 | COV-160 | [cover-218.webp](../assets/covers/by-release/cover-218.webp) |

`archive/cover-160.webp` — Jordan, а `by-release/cover-160.webp` — EISENHERZ. Одинаковый номер в разных папках обозначает разные вещи: номер исходной картинки и номер релиза. Это различие нужно учитывать при импорте. Код действующего сайта в рамках этой правки не проверялся, поэтому конкретная причина перестановки на сайте не установлена.

## Подключение на сайте

1. Обновить данные из [exports/catalog.json](../exports/catalog.json) и [assets/covers/release-map.json](../assets/covers/release-map.json) из одного и того же коммита.
2. Сопоставлять записи по `releaseId`, `catalogId` или UPC, брать путь изображения из `coverPath`. Индекс массива и номер файла из папки `archive` не определяют релиз.
3. Обновить пять файлов обложек, если сайт хранит их локальные копии. При необходимости обновить ключи кэша изображений; в карте доступен `sha256` каждой обложки.
4. Применить таблицу EISENHERZ/Jordan к карточкам сайта, показать название POLICE и опубликовать обновление сайта.

Подробная запись изменений: [catalog-owner-corrections-2026-09-12.json](../sources/catalog-owner-corrections-2026-09-12.json). Исторические наблюдения платформ остаются в исходном виде.
